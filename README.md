# FAQ bot — frontend

Адаптивный интерфейс по существующему Figma-файлу `Wb7SpMwSBK46PDOwgrHLsu`, страница «Макеты». React 19, TypeScript, Vite, React Router, Manrope, Lucide. Макеты в Figma не изменялись. Логотип экспортирован из оригинального компонента; UI собран из HTML и CSS. Все выпадающие списки используют общий компонент `Select` на Radix UI с управлением клавиатурой, оформлением в стиле приложения и поддержкой форм внутри диалогов. Ховеры рассчитаны на мышь; анимации учитывают `prefers-reduced-motion`.

## Запуск

Нужен Node.js 22+.

```sh
cd frontend
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5173`. На экране входа подойдёт любая корректная почта и пароль от 8 символов. Регистрация создаёт локальный демонстрационный профиль. Пароли не сохраняются и на сервер не отправляются.

```sh
npm run build     # TypeScript + production-сборка в dist/
npm run preview   # просмотр сборки
npm test          # браузерные сценарии, нужен установленный Google Chrome
```

## Работа без Go API

Приложение работает в локальном демо-режиме. Проекты, текст материалов, настройки виджета, заявки и ответы администратора сохраняются в `localStorage` под ключом `faq-demo-v1`. История тестового и посетительского чата — в `sessionStorage`. Для сброса удалить соответствующие ключи в инструментах браузера.

Файлы проверяются по формату и размеру (25 МБ); TXT можно прочитать локально. PDF/DOCX и медиа сохраняются как метаданные: разбор и транскрибация требуют сервера. Вложения поддержки сохраняются как имя файла. Аватар виджета сохраняется локально, ограничение 1 МБ.

Демо-чат использует заранее заданные ответы о возврате и доставке. Автопроверка показывает фиксированный набор вопросов и оценок; реальная генерация, определение ниши и оценка качества относятся к серверной интеграции. Аналитика использует демонстрационные показатели; счётчик неотвеченных диалогов связан с локальными данными. Пополнение токенов не вызывает платежей. Восстановление пароля не отправляет писем.

`src/api.ts` содержит типизированный transport и mock-маршруты состояния; `src/types.ts` — модели интерфейса. `/state` — внутренний демонстрационный контракт, его нельзя считать согласованным API Go. UI сейчас использует локальный store. Перед реальной интеграцией необходимо заменить операции store на сервисы с согласованными эндпоинтами. Переменные из `.env.example` предназначены для следующего этапа; установка `VITE_API_MODE=real` сама по себе не подключает UI к Go.

## CORS

Go-бэкенда в этой папке нет, поэтому серверная настройка CORS не изменялась. В Vite подготовлен dev-proxy: запросы `/api/*` направляются на `http://localhost:8080`. Так фронтенд сможет обращаться к одному origin в разработке. Для прямых запросов к другому домену Go-команда должна настроить разрешённый origin фронтенда, методы/заголовки, OPTIONS и при необходимости credentials. Точный контракт авторизации (cookie или bearer) ещё не согласован.

## Внешний виджет

`public/loader.js` — отдельный JS bundle без React. Он создаёт кнопку и iframe в Shadow DOM. Входящие сообщения проверяются по `event.origin`, `event.source`, типу и agent ID; исходящие отправляются на конкретный origin родительской страницы. Авторизация приложения не передаётся странице клиента. Loader загружает iframe с этого же frontend-домена.

```html
<script src="http://127.0.0.1:5173/loader.js" data-agent="acme" defer></script>
```

Скопировать код из настроек виджета. Для публичного сайта заменить localhost на доступный HTTPS-домен. Сейчас конфиг и история доступны только в локальном браузере: для реальной публикации, visitor session и REST-чата необходим Go API. Настройки цвета/позиции внутри preview работают; стартовая кнопка loader пока использует стандартный стиль, пока не появился публичный endpoint конфигурации.

## Проверки

Playwright проверяет регистрацию и совпадение паролей, создание проекта и материала, прогресс, чат, автопроверку, настройку и сохранение виджета, ответ в диалоге, мобильную навигацию, внешний iframe и контактную заявку. Отдельная проверка обходит 15 маршрутов при ширинах 1440/768/390/360 px и проверяет отсутствие ошибок JS и горизонтального переполнения. Скриншоты основных экранов лежат в `artifacts/`.
