# FAQ bot — frontend

Адаптивный интерфейс по существующему Figma-файлу `Wb7SpMwSBK46PDOwgrHLsu`, страница «Макеты». React 19, TypeScript, Vite, React Router, Manrope, Lucide. Макеты в Figma не изменялись. Логотип экспортирован из оригинального компонента; UI собран из HTML и CSS. Все выпадающие списки используют общий компонент `Select` на Radix UI с управлением клавиатурой, оформлением в стиле приложения и поддержкой форм внутри диалогов. Ховеры рассчитаны на мышь; анимации учитывают `prefers-reduced-motion`.

## Запуск

Нужен Node.js 22+.

```sh
cd frontend
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5173`. По умолчанию вход и регистрация обращаются к Go API. Нужен запущенный бэкенд на `http://127.0.0.1:8080` с PostgreSQL, миграциями и настроенным Supabase. На Go-сервере задайте `AUTH_ORIGIN=http://127.0.0.1:5173`, `APP_ENV=development` и `AUTH_ALLOW_INSECURE_HTTP=true` вместе с остальными обязательными настройками бэкенда. Используйте один адрес фронтенда, без смешивания localhost и 127.0.0.1.

`.env.example` содержит настройки клиента. При необходимости скопируйте его в `.env.local` и измените `API_PROXY_TARGET`. Для автономного просмотра интерфейсов установите `VITE_AUTH_MODE=mock` и перезапустите Vite. В этом режиме подходит любая корректная почта и пароль. `VITE_API_MODE=mock` управляет оставшимися демоданными кабинета отдельно от авторизации.

```sh
npm run build     # TypeScript + production-сборка в dist/
npm run preview   # просмотр сборки
npm test          # браузерные сценарии, нужен установленный Google Chrome
```

## Работа без Go API

Проекты, текст материалов, настройки виджета, заявки и ответы администратора пока работают на локальных данных. В mock-auth они сохраняются в `localStorage` под ключом `faq-demo-v1`, после настоящего входа — отдельно по компании в `faq-workspace-<account_id>`. История тестового и посетительского чата — в `sessionStorage`. Для сброса удалить соответствующие ключи в инструментах браузера.

Файлы проверяются по формату и размеру (25 МБ); TXT можно прочитать локально. PDF/DOCX и медиа сохраняются как метаданные: разбор и транскрибация требуют сервера. Вложения поддержки сохраняются как имя и размер файла, содержимое не загружается на сервер. Аватар виджета сохраняется локально, ограничение 1 МБ. Фото профиля: JPG/PNG до 2 МБ, проверяется возможность открыть изображение; фото, имя, почта и уведомления сохраняются вместе по кнопке «Сохранить изменения». «Отмена» восстанавливает сохранённые значения.

Новые страницы сверены с макетами Figma: настройки `68:738`, токены `70:1037`, поддержка `70:1215`. На телефоне поддержка переключается между списком и выбранной заявкой, история пополнений читается без горизонтальной прокрутки. Пакеты и способы оплаты доступны с клавиатуры; переключатели уведомлений имеют роль switch.

Демонстрация платежа открывается после выбора пакета и способа оплаты (карта/СБП); начисление тестовых токенов требует отдельного действия в диалоге. Деньги не списываются, статус истории помечен «Демо». Баланс относится ко всему аккаунту и обновляется в шапке. Запрос смены пароля показывает демоподтверждение без отправки письма. Включение уведомлений сохраняет предпочтения, рассылка требует сервера.

Для показа статусов и истории добавлены три примерные заявки и два примерных пополнения. Старые локальные данные обновляются однократно: существующие обращения, операции, профиль, проекты и баланс сохраняются. Примеры добавляются только при пустых списках первой версии. Ответы поддержки в примерах фиксированные; новые заявки получают локальное событие создания, без имитации реального ответа специалиста.

Демо-чат использует заранее заданные ответы о возврате и доставке. Автопроверка показывает фиксированный набор вопросов и оценок; реальная генерация, определение ниши и оценка качества относятся к серверной интеграции. Аналитика использует демонстрационные показатели; счётчик неотвеченных диалогов связан с локальными данными. Пополнение токенов не вызывает платежей. Восстановление пароля не отправляет писем.

`src/api.ts` содержит общий HTTP transport и mock-маршруты состояния, `src/types.ts` — модели интерфейса. `/state` — внутренний демонстрационный контракт. Авторизация использует работающие маршруты Go через `src/auth/api.ts`; остальные операции store ещё предстоит подключить к соответствующим сервисам. Установка `VITE_API_MODE=real` сама по себе не подключает остальные экраны к Go.

## Авторизация

Контракт взят из `GlebDesign/faq-bot-backend`, ветка `dev`, коммит `c69690b`, файлы `docs/AUTH.md` и `backend/internal/handlers/dto/auth.go`.

- При открытии входа, регистрации или кабинета выполняется `GET /api/v1/auth/session`. До ответа показана проверка сессии. При 401 открывается форма входа, при сетевой или серверной ошибке доступен повтор.
- Перед входом и регистрацией выполняется `GET /api/v1/auth/csrf`, затем `POST /api/v1/auth/login` или `/register` с `X-CSRF-Token` и JSON `{ email, password }`. Дополнительные поля сервер отклоняет.
- Сессия хранится сервером в HttpOnly-cookie. Клиент отправляет `credentials: include`, держит ответ с CSRF только в памяти и повторно проверяет сессию при возврате на вкладку и истечении абсолютного срока.
- Выход выполняет `POST /api/v1/auth/logout` с актуальным CSRF. При ошибке можно повторить выход. Cookie удаляет сервер.
- Имя, фото и настройки профиля пока локальные. Auth API возвращает identity без имени и email. При регистрации имя сохраняется локально под `faq-profile-<user_id>`; при входе используется введённая почта. Этот кеш не открывает доступ в кабинет и не определяет роль или компанию.
- Срок cookie задаёт Go API. Восстановление пароля и рассылка требуют отдельных серверных маршрутов.

Браузерные тесты реального клиентского режима используют ответы по контракту Go, включая cookie и CSRF. Подключение к живому Supabase требует отдельно запущенного и настроенного бэкенда.

## Стили по БЭМ

`src/styles/index.css` подключает общие токены, базовые стили, файлы блоков и анимации. Каждый блок находится в `src/styles/blocks/<block>/<block>.css`. Его адаптивные правила, hover и состояния находятся в том же файле.

Используется схема `block__element--modifier`, например `auth__form`, `sidebar__link--active` и `button--primary`. Общие элементы представлены блоками `button`, `field`, `select`, `panel`, `avatar`. Модификатор используется вместе с базовым классом. Раскладки находятся в `layout-row`, `layout-grid`, `layout-stack`, текстовые утилиты — в `text`. Для нового блока добавьте его файл в `index.css`.

## CORS

Vite направляет `/api/*` на `API_PROXY_TARGET`, по умолчанию `http://127.0.0.1:8080`. Go проверяет точный Origin, поэтому `AUTH_ORIGIN` должен совпадать с адресом страницы фронтенда. Текущий Go API не обслуживает CORS/OPTIONS. В production фронтенд и `/api` должны работать через общий HTTPS-origin с reverse proxy. Секреты Supabase остаются на сервере.

## Внешний виджет

`public/loader.js` — отдельный JS bundle без React. Он создаёт кнопку и iframe в Shadow DOM. Входящие сообщения проверяются по `event.origin`, `event.source`, типу и agent ID; исходящие отправляются на конкретный origin родительской страницы. Авторизация приложения не передаётся странице клиента. Loader загружает iframe с этого же frontend-домена.

```html
<script src="http://127.0.0.1:5173/loader.js" data-agent="acme" defer></script>
```

Скопировать код из настроек виджета. Для публичного сайта заменить localhost на доступный HTTPS-домен. Сейчас конфиг и история доступны только в локальном браузере: для реальной публикации, visitor session и REST-чата необходим Go API. Настройки цвета/позиции внутри preview работают; стартовая кнопка loader пока использует стандартный стиль, пока не появился публичный endpoint конфигурации.

## Проверки

Playwright проверяет регистрацию и совпадение паролей, создание проекта и материала, прогресс, чат, автопроверку, настройку и сохранение виджета, ответ в диалоге, мобильную навигацию, внешний iframe и контактную заявку. Отдельная проверка обходит 15 маршрутов при ширинах 1440/768/390/360 px и проверяет отсутствие ошибок JS и горизонтального переполнения. Скриншоты основных экранов лежат в `artifacts/`.

`tests/account.spec.ts` проверяет новые страницы: сохранение/отмену профиля и уведомлений, смену фото, запрос смены пароля, выбор пакета клавиатурой, отмену и подтверждение демо-пополнения, поиск и фильтры заявок, создание с вложением, историю, мобильный возврат и совместимость старых локальных данных. Новые экраны проверяются на ширинах 1440/1024/768/390/360 px.

`tests/auth.spec.ts` проверяет клиент в real-auth режиме с контрактными HTTP-ответами. Остальные тесты используют явный mock-auth. Playwright запускает два изолированных Vite-сервера на 5175/5176, чтобы проверки не зависели от пользовательского предпросмотра на 5173.
